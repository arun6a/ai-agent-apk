## What's New

### Fixed: Permission popup appears on every app launch
**Root cause:** `MainActivity.checkAllPermissions()` was called from `onResume()`, which fires every time the app comes to foreground. It used `AgentAccessibilityService.isRunning()` which returns the in-memory `instance` variable — but `instance` is null at app launch until `onServiceConnected()` fires (race condition). So the popup appeared every time, even when accessibility was actually enabled.

**Fix:** Added `AgentAccessibilityService.isEnabled(context)` companion method:
- Fast path: if `instance != null` → return true (definitely enabled)
- Slow path: queries `Settings.Secure.ENABLED_ACCESSIBILITY_SERVICES` from the actual Android system setting — the source of truth
- Compares against `"packageName/AgentAccessibilityService"` class name
- Returns true only if the service is actually enabled in Settings

`MainActivity.checkAllPermissions()` now uses `isEnabled(this)` instead of `isRunning()`.

### Made sandbox URLs configurable
**Problem:** All endpoint URLs (`/api/llm/proxy`, `/api/llm/vision`, `/api/web-search`) were hardcoded to a specific sandbox URL that was no longer reachable after a sandbox restart (new sandbox = new URL).

**Fix:** Added to `AIProvider`:
- `KEY_PROXY_BASE_URL` SharedPreferences key
- `DEFAULT_PROXY_BASE_URL` constant (current sandbox URL)
- `getProxyBaseUrl(context)` — reads from SharedPreferences or default
- `setProxyBaseUrl(context, url)` — write to SharedPreferences
- `getLlmProxyUrl(context)` — full URL for `/api/llm/proxy`
- `getVisionUrl(context)` — full URL for `/api/llm/vision`
- `getWebSearchUrl(context)` — full URL for `/api/web-search`

All hardcoded URLs removed from:
- `ToolExecutor` (`webSearch` tool, `analyzeScreenWithVLM`)
- `OverlayManager` (2 VLM callsites)
- `SettingsActivity` (Test API endpoint)
- `LLMClient` + `AIProviderSettingsActivity` (HTTP-Referer header now points to GitHub repo)
- `Config.kt` (removed stale `LLM_ENDPOINT` constant)
