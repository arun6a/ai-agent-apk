## What Changed

### NEW: ApiUsageTracker.kt
A new utility that tracks API usage across three levels:

**Per-Task** (resets each new user message):
- API calls made
- Prompt tokens used
- Completion tokens generated
- Elapsed time

**Per-Session** (resets when app process dies):
- Total calls
- Total tokens

**Per-Day** (resets at midnight):
- Total calls
- Total tokens
- Average tokens per call

### CHANGED: LLMClient.kt
Both response parsers now extract token usage:

**OpenAI format** (OpenRouter/Z.ai/Custom):
```json
{"usage": {"prompt_tokens": 320, "completion_tokens": 222}}
```

**Gemini format**:
```json
{"usageMetadata": {"promptTokenCount": 320, "candidatesTokenCount": 222}}
```

After parsing, calls `ApiUsageTracker.recordCall()` with the token counts and provider name.

### CHANGED: system_prompt.txt — Batching Enabled

**Rule 3 changed from:**
```
❌ DO NOT batch multiple action tools in one response.
   Execute one logical step at a time.
```

**To:**
```
✅ BATCH independent tools to save API requests.
   If tools don't depend on each other, call them ALL in one response.
   - BATCH: "check battery, time, wifi" → [getBatteryLevel, getCurrentTime, getNetworkInfo] (1 call)
   - BATCH: "remember name=X, list files" → [remember(name,X), listFiles(path)] (1 call)
   - SPLIT: "open youtube then search" → launchApp → [type, submitInput] (2 calls)
```

**Added CRITICAL section:**
```
## CRITICAL: Save API Requests (Batch Tools!)
- BATCH independent tools: if 3 things don't depend on each other, call all 3 in ONE response
- Only split into separate calls when step B depends on step A's result
- BAD: launchApp → readScreen → type → submitInput = 4 calls
- GOOD: launchApp → [type, submitInput] = 2 calls
- Aim for 2-3 calls per complex task, NOT 6-8
```
