## What Changed

### NEW: PluginManager.kt — Modular Tool Plugins

A plugin system that groups tools into JSON files. Only enabled plugins are included in the system prompt, saving tokens.

**Plugin format (JSON):**
```json
{
  "name": "WhatsApp",
  "description": "Send messages, read chats",
  "version": "1.0",
  "enabled": true,
  "tools": [
    {"name": "openWhatsAppChat", "params": ["phone", "message"], "description": "Open WhatsApp chat"}
  ],
  "prompt_section": "### WhatsApp Tools\n- openWhatsAppChat(phone, message?) — opens chat"
}
```

**Features:**
- Load built-in plugins from `assets/plugins/*.json`
- Load user-installed plugins from `filesDir/plugins/*.json`
- Enable/disable plugins via SharedPreferences
- Install/uninstall user plugins dynamically
- `getEnabledPluginsPrompt()` — injects only active plugin tools into system prompt
- `getEnabledToolNames()` — verify which tools the AI can call
- `getStatusReport()` — summary for Settings UI

## Architecture

```
User message
    ↓
LLMClient.chat()
    ↓
System Prompt = base_prompt + PluginManager.getEnabledPluginsPrompt()
    ↓
LLM sees only enabled plugin tools (saves tokens)
    ↓
ToolExecutor executes tools (tools exist regardless of plugin state)
    ↓
Response
```

### Token Savings (Projected)

| Mode | System Prompt Size | Tools Listed |
|------|-------------------|-------------|
| All plugins enabled (current) | ~4K tokens | 44 tools |
| Only 3 plugins enabled | ~2.5K tokens | 20 tools |
| Core only (no plugins) | ~1.5K tokens | 0 tools |

When a plugin is disabled, its tools are NOT listed in the system prompt — but the tool implementations still exist in ToolExecutor (backward compatible).
