## What's New

### 🔌 9 new event triggers for rules (the "wire more events" upgrade)

The v3.0.0 release had time + notification triggers only. This release wires up **all 9 missing event types** so the AI can create rules for almost any phone event.

### New: BootReceiver — rules survive phone reboot
- BroadcastReceiver for `ACTION_BOOT_COMPLETED` + `ACTION_LOCKED_BOOT_COMPLETED` + `ACTION_MY_PACKAGE_REPLACED`
- On boot, automatically reschedules all enabled time rules with AlarmManager
- Without this, AlarmManager alarms were lost after reboot → rules didn't fire until user opened the app

### New: BatteryRuleReceiver — battery_low + charging + discharging triggers
- BroadcastReceiver for `ACTION_BATTERY_CHANGED`, `ACTION_POWER_CONNECTED`, `ACTION_POWER_DISCONNECTED`
- For `battery_low` rules: checks if percent < threshold, with 30-minute cooldown to avoid repeat firing while still below threshold
- For `charging` rules: fires immediately when phone connects to power
- For `discharging` rules: fires when phone unplugs
- Uses SharedPreferences to track cooldown per rule

### New: IncomingCallReceiver — incoming call triggers
- Uses `TelephonyManager.PhoneStateListener` (NOT a BroadcastReceiver — must be registered programmatically)
- Registered in AgentService.onCreate(), unregistered in onDestroy()
- When phone rings (CALL_STATE_RINGING), looks up contact name via `ContactsContract.PhoneLookup`
- Matches rules by: `triggerValue="*"`, exact phone number, or contact name
- Dedupes within the same call (RINGING fires multiple times)

### New: SMSReceiver — incoming SMS triggers
- BroadcastReceiver for `Telephony.Sms.Intents.SMS_RECEIVED_ACTION`
- Matches rules by: `triggerValue="*"` (any), exact sender number, or body keyword
- Example: triggerValue="OTP" → fires on any SMS containing "OTP"

### New: HeadsetReceiver — headphone connect/disconnect triggers
- BroadcastReceiver for `ACTION_HEADSET_PLUG`
- Fires `headset_connected` when state=1, `headset_disconnected` when state=0

### New: ScreenReceiver — screen on/off + user unlock triggers
- BroadcastReceiver for `ACTION_SCREEN_ON`, `ACTION_SCREEN_OFF`, `ACTION_USER_PRESENT`
- NOTE: These actions can ONLY be registered programmatically (not in manifest)
- Registered as an anonymous BroadcastReceiver in AgentService
- `user_unlocked` fires only when the user actually unlocks (not on screen-on without unlock)

### New: WiFiReceiver — WiFi connect/disconnect triggers
- BroadcastReceiver for `WifiManager.NETWORK_STATE_CHANGED_ACTION`
- For `wifi_connected` rules: optionally matches SSID (triggerValue="MyHomeNetwork")
- Note: getting SSID requires ACCESS_FINE_LOCATION on Android 10+ (already declared)

### New: PackageReceiver — app install/uninstall triggers
- BroadcastReceiver for `ACTION_PACKAGE_ADDED` + `ACTION_PACKAGE_REMOVED`
- Intent filter includes `<data android:scheme="package" />` (required)
- Matches by: `triggerValue="*"` (any app) or specific package name

### New tools (in ToolExecutor)

- **`shareFile(path, mimeType?)`** — share a file via system share dialog using FileProvider
- **`openDialer(number)`** — open dialer with number prefilled (doesn't auto-call, user taps call button)
- **`openContact(id)`** — open a contact card by ID (use `searchContacts` first to get the id)
- **`openSettings(page)`** — deep-link to specific Settings page
  - Valid pages: wifi, bluetooth, location, accessibility, notification, apps, display, sound, battery, storage, datetime, language, developer, about, main

### Updated: createRule tool accepts 16 trigger types (was 4)
- Before: time, notification, battery_low, charging
- After: time, notification, battery_low, charging, discharging, incoming_call, sms_received, headset_connected, headset_disconnected, screen_on, screen_off, user_unlocked, wifi_connected, wifi_disconnected, app_installed, app_uninstalled
- All validate triggerType against the supported list and return helpful error for invalid types

### Updated: System prompt
- Added documentation for all 16 trigger types with `triggerValue` examples for each
- Added 6 new "WHEN TO CREATE A RULE" patterns (calls, SMS, headset, unlock, WiFi, app install)
- Added 6 new examples (Mom missed call, OTP saver, Spotify on headset, unlock briefing, home WiFi sync, app install check)
- Added 5 new app-action tools to the App Tools section (shareFile, openDialer, openContact, openSettings, shareText)

### New: FileProvider for secure file sharing
- Added `androidx.core.content.FileProvider` to manifest
- Created `app/src/main/res/xml/file_provider_paths.xml` with paths for external storage, internal files, cache, and root
- Used by the new `shareFile` tool to share files via system share dialog (Android 7+ requires FileProvider for `file://` URIs)

### New permissions
- `RECEIVE_SMS` — for SMS rules
- `READ_SMS` — for reading SMS content
- `READ_PHONE_STATE` — for incoming call listener
- `READ_PHONE_NUMBERS` — Android 12+ alternative for reading phone numbers

### Updated: AgentService registers programmatic receivers
- `IncomingCallReceiver` registered in `onCreate()` via `TelephonyManager.listen()`
- `ScreenReceiver` (anonymous BroadcastReceiver) registered for ACTION_SCREEN_ON/OFF/USER_PRESENT
- Both unregistered in `onDestroy()` to avoid leaks

## Known Issues
- **Permissions need to be granted by user** — new permissions (RECEIVE_SMS, READ_PHONE_STATE) require user approval on Android 13+. The app should prompt for these on first launch; if not, user must grant manually in Settings → Apps → AI Agent → Permissions.
- **NotificationListenerService restart** — if the user revokes notification access, NotificationListener stops and rules with `triggerType="notification"` won't fire. Need to detect this and prompt user to re-enable.
- **WiFi SSID matching on Android 10+** — requires ACCESS_FINE_LOCATION + location services enabled. If location is off, SSID will return `<unknown ssid>`.
- **PhoneStateListener is deprecated in API 31+** — should migrate to `TelephonyCallback` for Android 12+. Current code works on all versions but may show deprecation warnings.
- **No rule execution history yet** — planned for v3.2.0
- **No dry-run / preview** — planned for v3.2.0
