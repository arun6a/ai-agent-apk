## What's New

### Hybrid Browser Agent — structured page reading + Chrome fallback

The app now has a real browser agent with two modes:

**WebView mode (default)** — runs in background, invisible to user, full DOM access:
- `browserReadStructured()` — returns JSON with title, headings, links, buttons, inputs, forms, text. THE KEY TOOL — gives LLM page structure, not just text.
- `browserGetLinks()` — lists all visible links with text + URL
- `browserGetForms()` — lists all form fields with type, name, placeholder, value, coordinates
- `browserFillForm(field, value)` — smart form filling by label/name/id/placeholder matching
- `browserClickElement(selector)` — click by CSS selector
- `browserClickText(text)` — click by visible button/link text
- `browserGetText(selector)` — get text from specific element
- `browserWaitForElement(selector, timeout)` — wait for SPA content to load
- `browserScreenshot(prompt)` — capture page as image, send to VLM for description
- `browserScrollDown(pixels)` — scroll the page

**Chrome fallback** — for logged-in sites (Gmail, banking, social media):
- `openInChrome(url)` — opens URL in Chrome app, then use accessibility tools (readScreen, clickByText, type) to control it
- `searchInChrome(query)` — searches Google in Chrome

### What this enables

```
User: "check the price of iPhone 17 on Amazon"
AI: browserOpen("amazon.in/iphone-17")
    browserReadStructured() → sees buttons[], inputs[], text with price
    reply: "iPhone 17 is ₹79,900 on Amazon. There's a 'Buy Now' button."

User: "check my Gmail"
AI: openInChrome("gmail.com")  ← user is already logged in
    readScreen() → sees email list
    reply: "You have 3 unread emails..."

User: "fill this form on website X"
AI: browserOpen(url)
    browserGetForms() → sees fields: name, email, phone
    browserFillForm("name", "Arun")
    browserFillForm("email", "arun@example.com")
    browserFillForm("phone", "9003530697")
    browserClickElement("button[type=submit]")
    reply: "Form submitted."
```

## Known Issues
- WebView screenshot may not capture dynamically loaded content (images, canvas)
- Some sites block WebView user agent — may need to spoof Chrome UA (already set to Chrome 121)
- Chrome fallback requires accessibility service to be enabled
- No cookie/session management in WebView (each browserOpen starts fresh unless site uses localStorage)
- browserWaitForElement blocks the tool executor thread — may slow down other tools if called with long timeout
