## What Changed

### Important Correction to v3.2.2 Batching Change

**v3.2.2** said "BATCH independent tools" — too broad, caused problems:
- Batching `launchApp + type` caused "typing into AI Agent's own chat" bug
- Batching `type + submitInput` is risky (type might fail, submit sends nothing)

**v3.3.2** corrects to: "BATCH read-only tools, NEVER batch action tools"

### Updated System Prompt Rules

**Read-only tools (safe to batch):**
```
getBatteryLevel, getCurrentTime, getBluetoothState, getNetworkInfo,
getDeviceInfo, readScreen, listFiles, listInstalledApps, getCallLog,
getCalendarEvents, recall, recallAll, getClipboard, readContacts,
searchContacts, getCurrentLocation
```

**Action tools (NEVER batch — one per response):**
```
launchApp, type, clickByText, tap, swipe, submitInput, sendSMS,
callContact, setVolume, setBrightness, toggleFlashlight, setAlarm,
createRule, deleteRule, writeFile, deleteFile, copyFile, moveFile,
runShellCommand, openUrl, browserOpen, browserClick, browserFill
```

### Why This Matters

- Read-only tools don't change state — safe to batch, saves API calls
- Action tools change state — MUST verify each step before next
- Pattern: `action → readScreen (verify) → next action → readScreen (verify)`
