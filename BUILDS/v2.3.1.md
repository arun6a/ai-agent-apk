## What's New

### Fixed: "Accessibility service not running" false negative
**Root cause:** `ToolExecutor.executeTool()` called `AgentAccessibilityService.getInstance()` which returns the in-memory `instance` variable. This is null at app launch because Android calls `onServiceConnected()` asynchronously — even after the user has enabled accessibility in Settings, the instance is briefly null when the agent loop runs its first tool call.

**Fix:** Added `waitForAccessibilityService()` helper in `ToolExecutor`:
1. Fast path: returns instance if already bound
2. Slow path: if `isEnabled(context)` is true (system setting), polls for up to 5s (10 × 500ms) for the instance to bind
3. Only returns null if accessibility is actually disabled in Settings

Applied to both `executeTool()` and `analyzeScreenWithVLM()`.

### Fixed: OverlayManager floating button error
Same race-condition fix applied to `OverlayManager.onOverlayTapped()`:
- If `getInstance()` returns null but `isEnabled(context)` is true, shows a friendly toast: "Accessibility is enabled but service is still starting — try again in a moment"
- If accessibility is actually disabled, shows: "Accessibility not enabled" + TTS hint

## User Feedback That Drove This Fix
> "Ai responses for message but for all comments it's say please enable accessibility services are not running on your device. Please enable accessibility services in your device settings first. But i enabled already"

This was the classic "in-memory instance race condition" — system setting was correct but Android hadn't yet called `onServiceConnected()`.
