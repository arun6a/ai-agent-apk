## What's New

### Fixed: Agent brain — verify before claiming "Done!"

Major rewrite of the agent brain to stop the "BLACKPINK got typed into AI Agent's own chat" bug + "Done!" hallucination.

**Root cause:** The system prompt allowed batching 6 tools per response, so the LLM was sending `[launchApp, type, submitInput]` in one batch. `executeTools` ran them sequentially, but `launchApp` returns immediately (just calls `startActivity`) — YouTube hadn't actually loaded yet. The next `type("BLACKPINK")` ran while AI Agent was still foreground → typed into our own chat input. Then `submitInput()` triggered our own send button. The LLM assumed everything worked → "Done!" hallucination.

**Fixes:**

1. **`launchApp` now waits + verifies:**
   - Calls `service.launchApp(pkg)` → if false, returns error
   - Waits 2 seconds (gives target app time to swap to foreground)
   - Reads the screen via `service.readScreen()`
   - Returns `"launchApp(pkg) — launched. After 2s, screen shows: $shortScreen"` (200 chars truncated)
   - LLM sees the actual screen content and can decide next step

2. **`type()` and `submitInput()` abort if AI Agent is still foreground:**
   - Checks `ActivityManager.runningAppProcesses` for foreground package
   - If `currentPkg == "com.ai.agent"`:
     - Returns `"type($text) ABORTED: AI Agent app is still foreground. The previous launchApp did not complete. Try calling launchApp again, then readScreen() to verify."`
   - Prevents typing/submitting into our own chat input

3. **System prompt rewritten** — major changes:
   - "DO NOT batch multiple action tools in one response. Execute one logical step at a time, see its result, then decide the next step"
   - "NEVER trust tool results blindly. ALWAYS readScreen() after launchApp to verify"
   - "NEVER say 'Done!' or 'Task complete' unless you have called readScreen() and verified the result"
   - Added explicit step-by-step ordering for "open X and do Y" tasks

4. **Permission popup only on first launch:**
   - Uses SharedPreferences flag `first_launch_done`
   - Popup only shows on the very first launch, not every `onResume()`
   - Added `showPermissionSetupDialog()` as public method — user can trigger manually via menu

5. **CancellationException caught separately:**
   - Catches `kotlinx.coroutines.CancellationException` before generic `Exception`
   - Shows friendly message: "Task interrupted (a new message was sent or the task was stopped). Last progress: [workLog]"
   - Re-throws to preserve coroutine machinery

6. **`updateAccessibilityStatus` uses `isEnabled(this)`** instead of `isRunning()` (same fix as the permission popup from v2.2.2)
